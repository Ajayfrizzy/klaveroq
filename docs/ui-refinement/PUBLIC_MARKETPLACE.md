# Public marketplace milestone — local review

Branch: `staging`. No commit, push, merge, or deployment was performed. No production/beta database writes, resets, seeds, or migrations were performed.

1. **Product and visual experience.** `/` is now a public homepage for signed-out and signed-in visitors. It introduces the marketplace before registration, with Find work / Hire talent actions, open opportunities, six published talent previews, Discover → Agree → Deliver → Build reputation, a transparent trust section, audience-specific actions, and a footer. The visual system uses warm backgrounds, deep green text, restrained indigo actions, responsive cards, and an illustrated glass-card hero. The hero describes skills, agreed milestones, and delivery without fabricated people, ratings, balances, credentials, or transactions.

2. **Pages and compatibility.** `/jobs` is public opportunity discovery. `/jobs/[id]` renders public listings or, for an authorized participant only, an existing private agreement. `/talent` and `/talent/[userId]` are public discovery/profile pages. `/discover` and `/discover/[id]` remain compatible routes. The old signed-in homepage is preserved at `/dashboard`; agreement, listing, and proposal tabs remain at `/jobs?view=agreements`, `?view=listings`, and `?view=proposals`. The authenticated dashboard was moved rather than redesigned.

3. **Authorization and privacy.** The existing `profiles.isPublic` publication state remains authoritative. Directory/search/cursor queries filter published profiles, and both profile metadata and public profile pages use the public-only lookup. Owners edit unpublished profiles at `/profile`; unpublished public URLs no longer act as owner previews. Public job pages/API responses mask unpublished client profile fields as “Klaveroq client” and omit their reputation signals. Existing API authorization still protects proposals, agreements, messages, and preferences. Guest apply, post, invitation, saved-search, shortlist, profile, and dashboard actions lead to sign-in. Login/registration switches preserve a validated internal destination. Registration also preserves it through same-browser email verification when practical; Google authentication remains intact.

4. **Discovery.** The initial talent window is 24 profiles, with cursor-based next-page navigation. Default discovery orders eligible profiles by a deterministic hash of public profile ID + UTC day; each day's ordering is shared by server rendering and API responses. The cursor pins the day across midnight. The homepage takes six from that same published pool. Text search ranks exact name/role/skill matches first, headline/role matches next, and remaining matches last, rotating ties daily. Relevance takes precedence over alternate sort settings whenever a text search is present. Existing skills, role, category, availability, and real completed-work filters remain. Explicit reputation/completed/recent sorts remain available without a text query. Saved searches normalize the new default and relevance behavior.

5. **Reputation.** Native completed engagements, reviews, milestone counts, repeat clients, and on-time indicators retain their existing database-backed calculations. New profiles show neutral states, including “New on Klaveroq” in previews. Skills/availability remain labeled as self-reported in discovery. External reputation is presented separately from native history.

6. **Future Vellum boundary.** A small `ExternalReputationProvider` interface permits optional `did:ckb` and provider-attributed credential claims. Its only implementation returns `null`; the UI says “Credentials not connected.” No external API calls, fake claims, mandatory DID, wallet onboarding, or authentication replacement were added.

7. **Accessibility, performance, and metadata.** The hero uses CSS only, with fixed geometry and two quiet animation cycles. It disables animation and blur on mobile, and disables animation/transitions for reduced-motion users. No new dependencies, remote fonts, bitmap assets, or 3D renderer were added. Navigation supports mobile expansion, Escape, keyboard focus, and semantic landmarks. Public metadata uses `APP_URL` rather than a hard-coded unrelated origin; profile/job titles and descriptions are publication-safe. The community beta deliberately remains `noindex, nofollow`, with robots.txt disallowing crawling. Authorization does not depend on robots rules. Request-scoped React caching shares public detail lookups between metadata and page rendering; transient homepage preview failures use privacy-safe diagnostics and explicit unavailable states.

8. **Migration and beta configuration.** No schema or environment-file changes. Identity, uploads, funding, settlements, payouts, and refunds remain disabled as before. Only the repository's disposable loopback `klaveroq_test` database was initialized for tests. Existing beta data was not accessed by the test suites.

9. **Validation.** Final results are recorded below. Browser tests run a local production build with `DEPLOYMENT_STAGE=community_beta`, `IDENTITY_PROVIDER=disabled`, `IDENTITY_SANDBOX_ENABLED=0`, and `FILE_UPLOADS_ENABLED=false`. Added coverage exercises anonymous pages, private HTML/API/metadata safety, direct unpublished access, search, pagination, daily rotation, relevance across cursor pages, unpublishing, draft protection, protected actions, signed-in workflows, responsive overflow, reduced motion, and honest reputation. Existing profile/proposal transaction, account preference, email verification/recovery, dashboard, upload restriction, and identity restriction tests are included. Older dashboard unit tests now pin their clock to their September fixtures, avoiding calendar-dependent failures without changing financial logic.

10. **Screenshots.** Full-page Chromium captures at 1440×900 and 390×900 viewport sizes are in [`public-marketplace/`](public-marketplace/). They show disposable integration-test fixtures, not live marketplace endorsements or production users. Captures cover the homepage, jobs directory, talent directory, and public profile. The screenshot test waits for actual streamed content rather than photographing loading skeletons.

11. **Limits.** Rotation is deliberately simple, not a guarantee of equal impressions or an ML ranker. Hash sorting and the existing reputation aggregations should be profiled as traffic/work history grows; no production load test was run on the 1 GB instance. Guest profiles use initials, preserving existing media access restrictions. Credentials, payments, uploads, and identity verification remain unavailable by design. Verification links opened on another device may fall back to the dashboard. The selected browser suite uses Chromium with a narrow mobile viewport; the repository's entire historical screenshot/cross-browser suite was not run. Next.js occasionally logs “destination stream closed early” when tests immediately navigate away; the completed page tests pass.

12. **Before the grant demonstration.** Review the captured layouts and publishing copy, and have willing users publish real profiles and clients publish real opportunities. Empty marketplace sections intentionally show truthful empty states instead of demo inventory. Confirm the intended public `APP_URL` in the deployment environment and retain beta noindex until an explicit indexing decision. Deployment is a separate, unperformed step.
